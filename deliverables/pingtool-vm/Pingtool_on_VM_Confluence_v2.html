Pingtool (Vero Status) on a Linux VM

Jira: ASPF-1578 · Version: 4.3.0 · Owner: Quality AI Automation

Pingtool checks whether Vero is available and which model it uses, and shows the result on a web page. On a Linux VM it runs in the background and starts with the machine. You open the page on your laptop through the SSH connection; nothing is opened to the network.

1. Prerequisites

ItemCheck on the VM
SSH access to the VMssh <user>@<vm-host> logs in
Python 3.8 or newerpython3 --version
Vero CLI 2.3.x, signed invero version prints a version; vero auth has been done once
The release zipVero_Status_4.3.0.zip, attached to this page

2. Install

On your laptop (WSL or Git Bash), in the folder with the zip:

scp Vero_Status_4.3.0.zip <user>@<vm-host>:~/
ssh <user>@<vm-host>

On the VM:

mkdir -p ~/tools && cd ~/tools
python3 -m zipfile -e ~/Vero_Status_4.3.0.zip .
cd vero-status
bash scripts/install_vm.sh

The script checks Python and Vero, starts Pingtool in the background, and sets it to start with the VM (systemd user service, or crontab if systemd is not available). No sudo is needed. It ends with Vero Status is running on this VM, port 8767.

If it says it only runs while you are logged in, ask the VM admin once for: sudo loginctl enable-linger <user>

3. Open the page

FromHow
VS Code (Remote-SSH to the VM)PORTS tab › Forward a Port › 8767. Open the local address VS Code shows (it can be another port, e.g. 8768, if 8767 is used on your laptop).
A terminal on your laptopssh -N -L 8767:127.0.0.1:8767 <user>@<vm-host>, keep it open, then open http://localhost:8767. If 8767 is used on your laptop, use e.g. -L 9000:127.0.0.1:8767 and http://localhost:9000.

The page footer shows the VM name, so you know the checks run on the VM and not on your laptop.

4. Modes

ModeInstall commandWho sees it
Personal (default)bash scripts/install_vm.shYou, through the forwarded port. Also shows your own Vero sessions on the VM (CLI and VS Code Remote-SSH) and their response time.
Teambash scripts/install_vm.sh teamAnyone who can reach http://<vm-host>:8767, without login. Needs the port opened to the VM (request to IT). Settings only with the admin link; the key is in data/admin_key.txt.

5. Operate

All commands run in ~/tools/vero-status on the VM.

TaskCommand
Is it running?bash scripts/install_vm.sh status
Restartbash scripts/install_vm.sh (or … team) again
Logtail -f data/vero-status.log
Stop and remove the autostartbash scripts/install_vm.sh uninstall
Update to a new versionCopy the new zip to the VM, then in ~/tools: python3 -m zipfile -e ~/Vero_Status_<version>.zip . and bash vero-status/scripts/install_vm.sh. History and settings in data/ are kept.

6. Troubleshooting

SymptomFix
Vero CLI not foundOn the VM, run command -v vero and enter that path in Settings › Vero CLI location.
Not available: UnauthorizedRun vero auth on the VM.
Not running after a VM rebootLingering is off: ask the VM admin for sudo loginctl enable-linger <user>.
Page does not openCheck that the port forward is active and that status says running.
Vero needs a proxy on the VMSet HTTPS_PROXY in your shell, then run the install again. It copies the proxy settings for the background service.

7. Security

  • Each check sends one prompt (Reply with exactly: OK) to the cheap Haiku 4.5 model, every 15 minutes by default (96 a day; change in Settings).
  • No prompts, answers or secrets are stored. data/ (history, settings, log, admin key, proxy settings) is readable by your user only.
  • Personal mode listens on 127.0.0.1 only. Only your own processes and session logs are read, not those of other users on the VM.
