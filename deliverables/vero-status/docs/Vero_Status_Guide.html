Vero Status: user guide

A small program: double-click it and a dashboard opens in your browser, showing whether Vero is available and which model it uses.

Start it

  1. You need Python 3.8 or newer. If it is missing, install it from Software Center or python.org. Nothing else is needed.
  2. Put the vero-status folder somewhere fixed, for example C:\Tools\vero-status. If you received the source PDF, let your AI assistant rebuild the folder first (see Rebuild from the PDF below).
  3. Double-click Vero Status.pyw. Your browser opens http://127.0.0.1:8767. No command window appears. The first check takes about a minute.
  4. Optional: right-click Vero Status.pyw and choose Send to › Desktop (create shortcut). To start it together with Windows, press Win+R, type shell:startup, and put the shortcut in the folder that opens.

Double-clicking again while it runs just opens the dashboard. Quit on the page stops the program.

Response time of your own sessions

The panel Your Vero sessions (CLI and VS Code): response time shows how long the model takes to start answering when you work with Vero:

  • the median and the slowest 5 % (p95) over the last hour;
  • the median over 24 hours;
  • your last 40 model requests as bars. Hover a bar for its time, the model and the token count; red bars are failed requests. The dashed line is the median.

How it is measured:

  • Vero writes a log for every task, in %USERPROFILE%\.vero\data\tasks for the CLI and in the extension's storage under %APPDATA%\Code\User\globalStorage for VS Code.
  • Each model request is logged when it starts, and the model's first output is logged when it arrives. The difference is the response time, taken from Vero's own clock.
  • Only timestamps, model names and token counts are read. Your prompts and answers are never read, and nothing is changed.
  • The dashboard's own test questions are not counted. Untick My own Vero sessions in Settings to switch this off.
If the VS Code extension keeps its logs somewhere else, VS Code sessions will not appear. The panel then lists the folders it looked in, so the path can be added.

Each check asks Vero one tiny question: Reply with exactly: OK. It costs two small model calls and takes about a minute, because Vero starts a full agent each time. The check never auto-approves actions (no --yolo) and runs in an empty folder. Nothing Vero answers and no secret is stored.

Team server: one page for everyone, no login

Instead of every colleague running Vero Status, run it once on a server or an always-on PC and share one link. Viewers need nothing installed and do not log in or register.

  1. On the server, sign in to Vero with the functional account (vero auth), then run python vero_status_server.py in the folder. Optional: --port 8080.
  2. It prints a share link (http://<server>:8767/) and an admin link (…/?admin=<key>). Both are also in data\vero-status.log.
  3. Allow the port once in an administrator PowerShell: New-NetFirewallRule -DisplayName "Vero Status" -Direction Inbound -LocalPort 8767 -Protocol TCP -Action Allow
  4. To start it with the machine: Task Scheduler › Create Task › Run whether user is logged on or not, trigger At startup, program pythonw.exe, argument vero_status_server.py, Start in the folder, as the functional account.
WhoSees and can do
Anyone with the share linkAvailability, Vero's model, the model of the last check, 24 h availability, the last checks and Recent activity (time, result, model, answer time, who started it). Check now at most once every 5 minutes for everyone together.

The server page has no Quit button and does not show Vero open now or your sessions; those are about your own laptop, so keep using Vero Status.pyw locally for them. Plain HTTP is fine on the intranet; put IIS in front for HTTPS. Record the server, functional account and link in the SCMP.

Try it without Vero

In Settings › Vero CLI location, enter C:\Tools\vero-status\scripts\vero.cmd and save, then click Check now. A built-in fake Vero answers like the real one. Clear the field afterwards.

When something is wrong

You seeDo this
Vero CLI not found on this computerEnter the path from where vero in Settings.
Vero reported an error … UnauthorizedSign in to Vero again (vero auth).
Vero reported an error … provider unavailableVero or its model provider is down. Nothing to do on your side; the dashboard shows when it is back.
no answer within 150 sVero hung or is very slow. If it keeps happening, raise Give up after, or tell the Vero owners.
answered, but not with OKVero works (it counts as available), but the model or a guardrail answered differently.
"No Vero CLI or VS Code session open" while you use VeroYour Vero writes its logs to another folder. The latency panel lists where it looked. Send that list and the actual folder to the team.
Vero Status is not runningDouble-click Vero Status.pyw.
A message box says the port is in useAnother program uses port 8767. Change "port" in data\settings.json.

Details are in data\vero-status.log. To remove the program, click Quit, then delete the folder (and the shortcuts, if you made any). Earlier versions (Vero Latency Monitor, Vero Availability Monitor) keep calling Vero until you run uninstall.bat in their folders.

Rebuild from the PDF

If you received Vero_Status_4.2.0_Source.pdf instead of the folder, give it to Vero CLI or another AI assistant with: "Follow the instructions on page 1 of this PDF and rebuild the project in C:\Tools." The PDF contains every file with numbered lines and a verify script that confirms each file is exact. Then continue with Start it.
